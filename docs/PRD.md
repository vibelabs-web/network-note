# Product Requirements Document (PRD)
## Star Note - 네트워크 그래프 기반 지식관리 노트 앱

**버전:** 1.0  
**작성일:** 2024-12-25  
**목적:** 개인 지식관리용 네트워크 그래프 기반 메모 애플리케이션

---

## 1. 프로젝트 개요

### 1.1 비전
사용자의 메모를 별(Star)로 표현하고, 메모 간의 연결을 통해 지식 네트워크를 형성하는 개인 지식관리 도구. 제텔카스텐(Zettelkasten) 방법론을 기반으로 하여 메모 간의 유기적 연결을 강조하고, AI를 활용한 의미적 연결 제안을 제공한다.

### 1.2 핵심 가치 제안
- **심플한 메모 작성**: 마크다운 기반의 직관적인 메모 작성
- **명시적 연결**: 옵시디언/노션 스타일의 멘션([]로 다른 메모 참조) 기능
- **AI 기반 연결 제안**: 벡터 DB와 LLM을 활용한 의미적 연결 자동 제안
- **시각적 네트워크**: 연결 관계를 그래프로 시각화하여 지식 구조 파악
- **별 등급 시스템**: 연결 수에 따른 메모의 중요도 시각화

### 1.3 타겟 사용자
- 개인 지식관리 및 학습을 하는 사용자
- 제텔카스텐 방법론에 관심이 있는 사용자
- 메모 간의 연결을 통해 지식을 확장하고 싶은 사용자

## 2. 기능 요구사항

### 2.1 핵심 기능

#### 2.1.1 메모 작성 및 편집
- **마크다운 지원**: 표준 마크다운 문법 지원
- **실시간 미리보기**: 작성 중 실시간으로 렌더링된 결과 확인
- **자동 저장**: 일정 시간마다 자동 저장 (또는 실시간 저장)
- **제텔카스텐 ID**: 각 메모에 고유한 날짜 기반 ID 부여 (예: `2024-12-25-001`)

#### 2.1.2 멘션 시스템
- **명시적 연결**: `[[메모명]]` 형식으로 다른 메모 참조
- **자동 완성**: `[[` 입력 시 메모 목록 리스트로 표출, 사용자의 선택 후 페이지 자동 작성
- **양방향 연결**: A → B 연결 시 B의 연결 목록에도 자동 표시
- **연결 타입**: 
  - `explicit`: 사용자가 직접 생성한 연결
  - `suggested`: 시스템이 제안한 연결

#### 2.1.3 AI 기반 연결 제안
- **벡터 유사도 검색**: 임베딩 기반 유사 메모 검색
- **LLM 맥락 분석**: Ollama를 통한 의미적 연결 평가
- **제안 표시**: 새 메모 작성 시 관련 메모 제안
- **제안 승인/거부**: 사용자가 제안된 연결을 승인하거나 거부 가능
- **비동기 처리**: LLM 분석은 백그라운드에서 처리하여 UI 블로킹 방지

#### 2.1.4 네트워크 그래프 시각화
- **Force-directed Layout**: D3.js 기반의 물리 시뮬레이션 레이아웃
- **별 등급 시각화**: 연결 수에 따른 노드 크기 및 밝기 조정
  - 0개 연결: 외로운 별 (작고 희미)
  - 1-2개: 작은 별
  - 3-5개: 중간 별
  - 6-10개: 큰 별
  - 10개 이상: 중심 별 (hub, 밝고 크게)
- **인터랙션**: 
  - 노드 클릭: 메모 상세 보기
  - 노드 드래그: 위치 조정
  - 줌/팬: 그래프 탐색
  - 필터링: 연결 수, 태그 등으로 필터링

#### 2.1.5 메모 관리
- **CRUD 작업**: 생성, 읽기, 수정, 삭제
- **검색**: 제목, 내용, 태그 기반 검색
- **태그 시스템**: 메모에 태그 추가 및 태그별 필터링
- **목록 뷰**: 메모 목록을 리스트 형태로 표시
- **정렬**: 날짜, 제목, 연결 수 등으로 정렬

### 2.2 부가 기능

#### 2.2.1 데이터 관리
- **내보내기**: 메모를 마크다운 파일로 내보내기
- **가져오기**: 마크다운 파일에서 메모 가져오기
- **백업**: 데이터베이스 백업 기능

#### 2.2.2 사용자 경험
- **다크 모드**: 라이트/다크 테마 전환
- **키보드 단축키**: 빠른 작업을 위한 단축키 지원
- **반응형 디자인**: 다양한 화면 크기 지원

## 3. 기술 스택

### 3.1 Backend
- **Framework**: FastAPI (Python 3.13+)
- **Document DB**: MongoDB (로컬)
- **Vector DB**: ChromaDB (로컬)
- **LLM Runtime**: Ollama
- **LLM Model**: Llama 3.2 3B
- **Embedding Model**: all-MiniLM-L6-v2 (Sentence Transformers)

### 3.2 Frontend
- **Framework**: React 18 + TypeScript
- **Build Tool**: Vite
- **Markdown**: react-markdown + remark-gfm
- **Graph Visualization**: D3.js
- **Styling**: Tailwind CSS
- **State Management**: Zustand
- **HTTP Client**: Axios

### 3.3 개발 도구
- **Package Manager**: Poetry (Python), pnpm (Node)
- **Container**: Docker (선택사항, MongoDB/Ollama용)

## 4. 데이터 모델

### 4.1 메모 (Memo)
```typescript
interface Memo {
  _id: ObjectId;
  zettelId: string;           // 제텔카스텐 ID (예: "2024-12-25-001")
  title: string;              // 메모 제목
  content: string;            // 마크다운 내용
  createdAt: DateTime;
  updatedAt: DateTime;
  connections: Connection[];   // 연결 목록
  mentions: string[];         // @멘션된 메모명 목록
  tags: string[];             // 태그 목록
  embedding?: number[];       // 임베딩 벡터 (선택적, ChromaDB에 저장)
}
```

### 4.2 연결 (Connection)
```typescript
interface Connection {
  targetId: ObjectId;         // 연결 대상 메모 ID
  type: "explicit" | "suggested";
  strength: number;           // 연결 강도 (0.0 ~ 1.0)
  createdAt: DateTime;
}
```

### 4.3 벡터 저장 (ChromaDB)
- Collection: `memos`
- Documents: `{ id: memoId, embedding: number[], metadata: { title, zettelId } }`

## 5. API 명세

### 5.1 메모 API

#### `GET /api/memos`
메모 목록 조회
- Query Parameters:
  - `page`: 페이지 번호 (기본값: 1)
  - `limit`: 페이지당 개수 (기본값: 20)
  - `sort`: 정렬 기준 (`createdAt`, `updatedAt`, `connections`)
  - `tag`: 태그 필터
  - `search`: 검색어

#### `GET /api/memos/{memo_id}`
특정 메모 조회

#### `POST /api/memos`
새 메모 생성
- Request Body:
  ```json
  {
    "title": "메모 제목",
    "content": "마크다운 내용",
    "tags": ["태그1", "태그2"]
  }
  ```

#### `PUT /api/memos/{memo_id}`
메모 수정

#### `DELETE /api/memos/{memo_id}`
메모 삭제

### 5.2 연결 API

#### `POST /api/connections`
연결 생성
- Request Body:
  ```json
  {
    "sourceId": "memo_id",
    "targetId": "target_memo_id",
    "type": "explicit"
  }
  ```

#### `DELETE /api/connections/{connection_id}`
연결 삭제

#### `GET /api/memos/{memo_id}/connections`
특정 메모의 연결 목록 조회

### 5.3 제안 API

#### `GET /api/memos/{memo_id}/suggestions`
연결 제안 조회
- Query Parameters:
  - `limit`: 제안 개수 (기본값: 10)
  - `useLLM`: LLM 재평가 사용 여부 (기본값: false)

#### `POST /api/suggestions/refine`
LLM을 통한 제안 재평가 (비동기)
- Request Body:
  ```json
  {
    "memoId": "memo_id",
    "candidateIds": ["id1", "id2", ...]
  }
  ```

### 5.4 그래프 API

#### `GET /api/graph`
전체 그래프 데이터 조회
- Response:
  ```json
  {
    "nodes": [
      {
        "id": "memo_id",
        "label": "메모 제목",
        "connections": 5,
        "level": 3
      }
    ],
    "edges": [
      {
        "source": "memo_id_1",
        "target": "memo_id_2",
        "type": "explicit",
        "strength": 0.8
      }
    ]
  }
  ```

## 6. UI/UX 요구사항

### 6.1 메인 레이아웃
- **사이드바**: 메모 목록, 검색, 태그 필터
- **에디터 영역**: 메모 작성/편집
- **그래프 뷰**: 네트워크 그래프 시각화 (전체 화면 또는 분할 뷰)

### 6.2 메모 에디터
- **분할 뷰**: 왼쪽 에디터, 오른쪽 미리보기
- **멘션 자동완성**: `[[` 입력 시 드롭다운 표시
- **자동 저장 인디케이터**: 저장 상태 표시
- **마크다운 툴바**: 기본 서식 버튼 (선택사항)

### 6.3 그래프 뷰
- **전체 화면 모드**: 그래프에 집중할 수 있는 모드
- **노드 스타일**: 연결 수에 따른 크기/밝기 차별화
- **엣지 스타일**: 연결 타입에 따른 색상 구분
  - 명시적 연결: 진한 색
  - 제안 연결: 연한 색 (점선)
- **컨트롤**: 줌 인/아웃, 리셋, 필터

### 6.4 연결 제안 UI
- **제안 배지**: 새 메모 작성 시 관련 메모 제안 표시
- **승인/거부 버튼**: 각 제안에 대해 승인 또는 거부
- **제안 이유**: 왜 이 메모가 제안되었는지 간단한 설명

## 7. 제텔카스텐 방법론 적용

### 7.1 Zettel ID 시스템
- 형식: `YYYY-MM-DD-XXX` (예: `2024-12-25-001`)
- 날짜 기반으로 시간순 정렬 가능
- 계층 구조 표현 가능 (필요시)

### 7.2 연결 원칙
- **느슨한 연결**: 관련이 있지만 직접적이지 않은 연결
- **끈끈한 연결**: 강한 의미적 관계를 가진 연결 (다수 가능)
- **상호 참조**: A ↔ B 형태의 양방향 연결

### 7.3 지식 네트워크 형성
- 연결이 없는 메모는 고립된 별로 표시
- 연결이 많아질수록 중심(hub) 역할
- 네트워크를 통해 새로운 통찰 발견

## 8. 성능 요구사항

### 8.1 응답 시간
- 메모 CRUD: < 100ms
- 벡터 검색: < 500ms
- LLM 제안: < 5초 (비동기 처리)
- 그래프 렌더링: < 1초 (100개 노드 기준)

### 8.2 처리량
- 동시 사용자: 1명 (개인 사용)
- 메모 수: 최대 10,000개 지원 목표

### 8.3 리소스 사용량
- 메모리: < 4GB (LLM 포함)
- 디스크: 메모당 평균 10KB 가정
